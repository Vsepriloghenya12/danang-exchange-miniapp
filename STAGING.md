# Тестовая версия в Telegram

Ветка для нового функционала: `codex/new-features`, создана от `main` (`c4408c8`).
Тестовый бот: [@testcashalot_bot](https://t.me/testcashalot_bot).

## Настроенное окружение

- Проект: «обменник», аккаунт Cash a Lot.
- [Окружение staging](https://railway.com/project/d17a972f-f605-4d88-a1f0-c5cd911ce2d1?environmentId=0f1345a1-eaec-4a5b-ac62-1b256c0de3b1).
- Сервис: `cashalot-test`, ветка `codex/new-features` с автоматическим развёртыванием.
- Адрес: https://cashalot-test-staging.up.railway.app.
- Отдельная база: `Postgres-ZW5_` в `staging`.
- `DATABASE_URL` ссылается на `${{Postgres-ZW5_.DATABASE_URL}}`.
- Файлы приложения сохраняются на отдельном томе в `/data`.

Токен тестового бота задаётся в `BOT_TOKEN` через Railway Variables.
Для доступа владельца указать его числовой Telegram ID в `OWNER_TG_IDS`.
Для отдельного входа через `/admin` задать секрет `ADMIN_WEB_KEY`.
Для проверки доставки заявок и публикации курсов задать тестовые
`REQUESTS_GROUP_CHAT_ID` и `GROUP_CHAT_ID`.

## Подключение

1. Сохранить токен бота `@testcashalot_bot` из https://t.me/BotFather
   в переменной `BOT_TOKEN` тестового сервиса Railway.
2. Ветка `codex/new-features` опубликована в GitHub и готова к подключению.
3. В проекте Railway создать пустое окружение `staging` и сервис из этого
   репозитория с веткой `codex/new-features`. Использовать корень репозитория.
4. Использовать сборщик Railpack, команду сборки `npm run build`, команду
   запуска `npm start`, проверку доступности `/api/health`.
   Railpack устанавливает зависимости на отдельном шаге; повторный `npm ci`
   в команде сборки конфликтует с подключённым кешем Vite (`EBUSY`).
5. Добавить отдельный PostgreSQL в `staging`. Переменная `DATABASE_URL`
   приложения должна ссылаться на эту тестовую базу.
6. Создать для тестового сервиса HTTPS-домен. Задать его в `WEBAPP_URL`
   и `PUBLIC_URL`. Заполнить остальные переменные по `server/.env.staging.example`.
7. Для сохранения загруженных файлов подключить отдельный volume к `/data`.
8. Запустить сервис после заполнения настроек. В Telegram отправить новому
   боту `/start` и нажать «Открыть мини-приложение».

Сервис работает в режиме `ROLE=monolith`: API, интерфейс и бот в одном процессе.
При запуске он регистрирует webhook для токена `BOT_TOKEN` на `PUBLIC_URL`.
Поэтому тестовому сервису нужны собственные токен, домен, база и группы Telegram.
Курсы и настройки тестовой базы заполняются через `/admin` тестового домена.

## Проверка после запуска

- `/api/health` возвращает `{"ok":true}`.
- В логах есть успешные `getMe OK` и `Webhook set` для тестового бота.
- Мини-приложение открывается через `/start`, авторизация Telegram проходит.
- В тестовой админке сохраняются курсы и наценки; калькулятор их применяет.
- Заявка приходит в тестовую группу, отображается в админке и меняет статус.
- Уведомление о смене статуса приходит тестовому пользователю.
- После перезапуска сохраняются тестовые настройки и заявки.

## Страница владельца и действия пользователей

- На вкладке «Курс» кнопки сохранения, очистки и загрузки находятся над кросс-парами.
- Вкладка «Касса» удалена.
- Вкладка «Действия» показывает уникальных клиентов на каждом этапе: запуск бота,
  открытие приложения, просмотр курсов, ввод суммы, нажатие отправки, создание
  заявки и завершение обмена. Владелец и сотрудники исключаются из отчёта.
- Период выбирается по времени Дананга, максимум 90 дней. Отчёт обновляется
  каждые 30 секунд, пока вкладка браузера видима.
- Карточки «Где остановились» фильтруют клиентов без заявки или обмена,
  с введённой суммой без отправки, а также с нажатием отправки без созданной заявки.
  Учитывается посещение приложения; человек может ещё заполнять форму.
- Поиск работает по имени, username и Telegram ID. Раскрытие клиента показывает
  последние 50 действий за период и последнюю введённую сумму.
- Заявки и завершённые обмены берутся из серверных записей. Повторные события
  не увеличивают число уникальных клиентов; браузер не может записать завершение
  обмена или запуск бота через API событий.
- Сбор новых событий начинается после обновления. Прежние вводы сумм и просмотры
  курсов не восстанавливаются. При превышении 50 000 событий отчёт предупреждает,
  что нужно сократить период.

### Проверка действий в тестовом боте

1. С клиентского аккаунта отправьте `/start` в `@testcashalot_bot`.
2. Откройте мини-приложение, посмотрите курсы, введите сумму и закройте приложение.
3. Владелец открывает «Действия» → «Сегодня»: клиент появляется в списке
   «Ввели, не отправили», а в истории видна сумма и валюта.
4. В рабочее время создайте заявку. В новом посещении отправленная заявка
   учитывается отдельно от предыдущего незавершённого ввода.
5. После подтверждения завершения обмена клиент учитывается в «Завершили обмен».

## Реферальная программа

- В шапке мини-приложения кнопка с человеком и плюсом открывает приглашение,
  бонусный счёт и историю. Ссылка отправляется через выбор чата Telegram.
- Приглашение закрепляется при первом `/start ref_ID` или первом входе с
  подписанным `start_param=ref_ID`. У существующих клиентов пригласивший не меняется.
  Telegram ID — единственный идентификатор участника. Самоприглашения запрещены.
- Лимит — 20 новых приглашений на человека в сутки UTC. При превышении новый
  клиент может пользоваться сервисом, но приглашение и бонус не засчитываются.
  Лимит не доказывает, что разные Telegram-аккаунты принадлежат разным людям;
  менеджер проверяет фактический обмен перед завершением.
- Друг получает эквивалент 50 000 VND, пригласивший — 0,5% суммы, которую друг
  отдал при первом завершённом обмене. Оба бонуса хранятся в целых центах USD.
- Для пересчёта сохраняется курс обменника при создании заявки: сумма USD
  учитывается напрямую, VND делятся на курс продажи USD, остальные валюты
  переводятся через их курс покупки в VND и курс продажи USD. Последующие
  изменения дневных курсов не меняют заявку. При редактировании заявки менеджером
  используется итоговая сумма и сохранённые курсы. Если нужных курсов нет,
  реферальная заявка не создаётся — сначала заполните курсы на текущий день в Дананге.
- Кнопка «Готово» требует подтверждения полного получения денег и завершения
  обмена. Оба начисления и статус сохраняются одной транзакцией. Повторные запросы
  не начисляют бонус повторно. Подтверждённую сделку нельзя отменить или открыть заново.
- В уведомлении менеджеру есть баланс на момент создания заявки. В карточке
  клиента — текущий баланс и количество приглашённых.
- Владелец видит вкладку «Рефералы»: кто кого привёл, завершённые объёмы по валютам,
  бонусы обоим и историю. После фактической выдачи бонусов запишите списание USD
  с комментарием о выданной валюте. Кнопка учитывает выдачу, перевод денег выполняется
  владельцем отдельно. Повтор отправки той же операции не списывает деньги дважды.

### Проверка в Telegram

1. В тестовой админке сохраните курсы текущего дня, включая USD BUY/SELL.
2. В `@testcashalot_bot` откройте меню приглашений и отправьте ссылку другому
   Telegram-аккаунту, который ещё не запускал этого тестового бота.
3. Новый аккаунт нажимает Start и открывает мини-приложение. В «Рефералах» владельца
   появляется приглашение с нулевым бонусом.
4. В рабочее время создайте обмен, убедитесь, что менеджер получил строку «Бонусы».
5. Сначала проверьте отмену: начислений быть не должно. Создайте новую заявку,
   завершите её в админке и подтвердите получение денег.
6. Проверьте оба счёта, историю и объёмы во вкладке владельца. Второй обмен этого
   клиента не должен давать новый реферальный бонус.
7. Запишите тестовую выдачу части бонуса: остаток должен уменьшиться на эту сумму.

Пример: первый обмен 1 000 USD при USD SELL = 25 000 VND даёт другу 2 USD,
пригласившему 5 USD. За отменённую заявку — 0 USD.
